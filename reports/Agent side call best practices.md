# Most side calls survive; their reasons don't

The audit's keep-or-delete calls mostly hold, but five of its stated reasons or fixes do not. Delete only diagnose's model step, and pause skill promotion until something can review or test its output. The most urgent item is not a model question: the terminal risk assessor has logged nothing, and the code shows why that is probably a configuration or allowlist effect rather than a build problem. A deterministic allowlist that sits ahead of it can settle whole interpreters such as `python3`, which is the case the assessor exists to judge. The second is observability. Six different code paths make these calls, only the router and the two safety judges record failures, and several log the requested model rather than the one that answered, so every "calls versus writes" figure in the audit counts successes only. Position (a) is half right: the failure policies should differ, but the plumbing and the recording should not. Position (b) is right about coverage and incomplete as a fix. Almost nothing here rests on a controlled test of a side-call design; the literature is strong on what shipped systems do and weak on whether it works.

Evidence tags used below: **[primary]** is a vendor's own docs or source describing behaviour, **[vendor]** is a self-reported number, **[preprint]** is a single-group arXiv result without visible replication, **[third-party]** is someone else's account, **[inference]** is my reasoning, **[code]** was read in this repository at commit 50bfcba, and **[local]** is aidaemon's own measurement.

## Six practices define a good side call, and no call meets all six

The first practice is to choose the shape by what the call needs. No source argues for routing everything through the loop, and shipped agents use a spectrum of plain calls, cache-sharing forks and subagents ([Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)) **[primary]**. A judge should stay outside the loop because Anthropic's design strips assistant text and tool results so injected content cannot argue with the classifier ([Anthropic auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)) **[primary]**. Codex is the counter-example: its reviewer receives a compact transcript with tool outputs and can run read-only checks ([Codex auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)) **[primary]**. The two leading vendors disagree, and no head-to-head under adaptive attack exists.

The second practice is to declare a failure policy for each call. Judges fail closed everywhere examined ([Claude Code permission modes](https://code.claude.com/docs/en/permission-modes)) **[primary]**, and a reviewer that could not run must be distinguished from one that said no; Codex tells the agent "a timeout alone is not proof" of danger ([Codex auto-review](https://learn.chatgpt.com/docs/sandboxing/auto-review)) **[primary]**. Retry must be bounded by one absolute deadline at one layer ([Google SRE](https://sre.google/sre-book/addressing-cascading-failures/)), which is 2016 server guidance but still the reference. Quota, auth and bad-request errors stay out of ordinary retry ([OpenAI rate limits](https://developers.openai.com/api/docs/guides/rate-limits), [Claude Code model config](https://code.claude.com/docs/en/model-config)) **[primary]**.

The third practice is to justify the model tier with an evaluation of that call. Anthropic and OpenAI both make a local benchmark the deciding step ([Anthropic](https://platform.claude.com/docs/en/about-claude/models/choosing-a-model), [OpenAI guide](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)) **[primary]**. Neither vendor's safety checker defaults to its top model. The fourth is to prove the call ran: Prometheus advises zero-valued series and last-success timestamps ([Prometheus](https://prometheus.io/docs/practices/instrumentation/)) **[primary]**, Claude Code tags every request `main`, `subagent` or `auxiliary` ([Claude Code monitoring](https://code.claude.com/docs/en/monitoring-usage)) **[primary]**, and no LLM-specific recipe for detecting a silent non-execution exists. Anthropic's own table shows an advisor consulted on 0 of 198 questions while still adding token overhead ([Anthropic](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)) **[vendor]**.

The fifth is to treat every automatic write and judge input as attackable. Adaptive attacks broke 12 recent defenses, most above 90% success ([The Attacker Moves Second](https://arxiv.org/abs/2510.09023)) **[preprint]**, and memory channels with more aggressive writing are more exploitable ([MPBench](https://arxiv.org/pdf/2606.04329)) **[preprint]**. The sixth is to keep a call only if removing it changes an outcome, by removing one component at a time ([Anthropic harness design](https://www.anthropic.com/research/harness-design-long-running-apps)) **[vendor]**, measured in repeated runs ([Anthropic evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)) **[primary]**.

|---|---|---|---|---|---|
| Router | Untested | Yes | Yes | No | Partly: up to two tool-row summaries, typed output only |
| Verifier | Yes | Mostly | Yes | No | Partly: arguments fenced, no adaptive test |
| Assessor | Yes, if reached | Mostly | Yes, but no rows exist | No | Partly: silent file skips |
| Summarizer | Yes | Partly | Successes only | No | Yes: tainted tool output replaced |
| Interpreter | Untested | Yes | No | No | Partly: tool-less, can still mislead |
| Diagnose | Weak | Yes | Successes only, requested model | No | Not tested |
| Progressive extraction | Untested | Partly | Successes only | Partly | Yes: role and visibility gate |
| Task learning | Untested | Partly | Successes only | No | **No** |
| Fact consolidation | Yes | Yes | Successes only, requested model | Partly | Partly |
| Session analysis | Yes | Yes | Successes only, requested model | Partly | Partly |
| Procedure enhancement | Yes | Single provider, harmless fallback | Successes only, requested model | No | Not tested |
| Skill promotion | Untested | Yes | Successes only, requested model | No | Partly: recurrence gate only |

## The safety pair is sound in shape and weak at the edges

The verifier matches the audit on isolation and on failing closed **[code]** (`src/agent/runtime/untrusted.rs`). It is tool-less, runs at low effort, shares a 20-second deadline across all candidates, does not fail over on a timeout, and never moves on after a completed verdict. That last rule is stricter than Codex's denial resampling, and it fits the finding that resampling acts like best-of-n for an attacker ([Terekhov et al.](https://arxiv.org/pdf/2510.09462)) **[preprint]**.

"Primary model" is only the first attempt. `ask_for_judgment` treats auth, billing, quota, rate limit, not-found, timeout, network and server errors as infrastructure, then tries each failover provider's models fast tier first (`src/llm_runtime.rs:205`, `src/providers/error.rs:325`) **[code]**. I found no shipped agent that fails a judge over across vendors. Claude Code's only documented fallback stays with the same vendor and moves toward the session model ([permission modes](https://code.claude.com/docs/en/permission-modes)) **[primary]**. Calibration shift across vendors has not been measured, so an unevaluated fast model can return a confident approval where an honest no-verdict was available **[inference]**. The November 8 commit that added this for the assessor has a real motive, since a used-up plan otherwise turns every command into an approval card. That argues for keeping failover on a short list of tested candidates, ordered strongest first, and not for removing it.

One research note overstates the verifier's narrowness. It says the verifier sees only the original request, but root turns judge against a request lineage from `owner_request_for_verifier`, added because a bare "try again" lost its subject (`src/agent/runtime/sdk_engine.rs:1401`) **[code]**. The real gap is smaller: one request, not all owner messages, so a later owner message forbidding a destination is invisible unless it is the lineage. Claude Code and Codex both supply more owner history ([permission modes](https://code.claude.com/docs/en/permission-modes), [Codex instructions](https://github.com/openai/codex/blob/main/codex-rs/ext/guardian-reviewer/src/instructions.rs)) **[primary]**. Test that case in both directions. Two smaller fixes apply to both judges: both fall back to `response.thinking` when content is absent, and the assessor extracts any `{...}` span from it, so reasoning that quotes attacker JSON could be read as a verdict **[code]**. I found no per-run denial budget in the code I searched, while both vendors have one; NIST's jump from 57% to 80% attack success across 25 attempts shows why it matters ([NIST](https://www.nist.gov/news-events/news/2025/01/technical-blog-strengthening-ai-agent-hijacking-evaluations)).

The assessor's silence can be narrowed, though not settled, from code. `assess_command` is wired at startup (`src/startup/tools.rs:129`), was wired in the v0.12.9 tag, and its records are enabled because `TerminalTool` is built with both an event store and a state store **[code]**. That makes "the deployed build cannot reach it" unlikely for any build after mid-August, unless the deployed binary is older still. "Earlier branches settle every command" has four auto-approving routes in `approval_ladder` (`src/tools/terminal.rs:3734`), and the other earlier branches ask the owner and so would show as approval cards. The four are a trusted scheduled session, an owner trust-all grant persisting `*` to `terminal_backend_allowed_prefixes`, `permission_mode = yolo` adding the same `*`, and an allowlisted prefix **[code]**. The checked-out `config.toml` sets no YOLO mode but allowlists `python3`, `git`, `pip` and `rm` **[code]**. Whether those routes account for all 349 calls needs the database or the daemon log, which I did not query. Selecting `prefix = '*'` from that table and counting the ladder's `Auto-approved:` log lines per branch will settle it. Also check how the audit filtered: these rows are filed under the turn's session with purpose `terminal_command_risk`, not under a `background:` session like most side calls **[code]**.

If the allowlist is the cause, the audit's "keep the design" is too generous. `python3 script.py` passes on prefix alone, so the assessor's script-reading feature never fires on the commonest interpreter. Claude Code drops wildcarded interpreter and package-manager rules on entering auto mode for this reason ([permission modes](https://code.claude.com/docs/en/permission-modes)) **[primary]**. A real assessor also needs its input rules tightened. Unreadable, binary or out-of-workspace references are skipped silently, and truncation is flagged without being treated as unknown **[code]**, against the rule that such content is unknown rather than benign **[inference]**. A shadowing module or a package lifecycle script can hide behind a referenced-file scan, as a multi-step chain did against Opus 5 auto mode in 3 or 4 of 5 tries ([Embrace The Red](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)) **[third-party]**. OpenAI states that Auto-review is not a security guarantee ([OpenAI](https://alignment.openai.com/auto-review/)) **[primary]**, so a sandbox has to backstop whatever the assessor misses.

## The router's 0/8 measured a system that no longer exists

The A/B result is real for what it tested: 8/8 against 0/8 on tool-only follow-ups gives a two-sided Fisher p of about 0.0002 by my calculation **[local, inference]**, while 8/8 against 5/8 (p of 0.2) and 8/8 against 6/8 (p of 0.47) are not distinguishable from noise. Its cause was the off arm having no tool history. The same-day fix, `session_context_note` in `src/tools/search_history.rs:601`, takes only a session id and reads the event log, so it should reach a router-off turn too **[code]**. The project note reports 8/8 after the fixes and records no post-fix run with the router off **[local]**. So "must run before the loop" is an open claim.

Public evidence does not resolve it. Claude Code resends all history and documents no per-turn relationship classifier in the pages read ([Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching)) **[primary]**, which shows no such call is required but says nothing about aidaemon's turn assembly, where a new request drops earlier tool calls. Keep the router until the missing arm runs. The design itself follows practice: fast tier first, one attempt per candidate, a fair share of a 45-second budget, and full per-attempt failure records (`src/agent/turn/bootstrap/task_planning.rs:386`) **[code]**. Forty-five seconds is well above the 2 to 6 seconds published for LLM intent classifiers ([Xie et al.](https://aclanthology.org/2026.customnlp4u-1.8.pdf)), so report p95 and deadline hits, and report error by direction, because a false `new_request` causes a false denial while a false `continuation` only adds context **[inference]**.

## Memory calls differ more by risk than by plumbing

Task learning is the one memory verdict that changes on safety grounds. Its log includes 300-character previews of tool results, and neither the caller in `src/agent/runtime/spawn.rs`, nor `src/memory/task_learning.rs`, nor the crate's learner checks taint **[code]**. In one study, 10% attacker-supplied records embedded target behaviour in 91% of SkillClaw trials ([Trajectory Poisoning](https://arxiv.org/abs/2608.05563)) **[preprint]**, and content screening refused none of 360 poisoned memories in another ([Utility Under Attack](https://arxiv.org/pdf/2608.21230)) **[preprint]**. Both are single-group results in controlled settings, so the size of the risk here is unknown. The direction is enough to put the gate ahead of failover.

Skill promotion's real gate is stricter than the research notes assumed: with `learning_evidence_gate_enforce` on by default it needs 7 successes, 90%, and a margin of 3, not 5 and 80% (`src/skills/promotion.rs:26`) **[code]**. It still measures recurrence and not causation. Executable or replayable checks are what separate positive results from null ones: MUSE-Autoskill reached 60.35% against 53.19% with no skills, using tests before registration ([MUSE-Autoskill](https://arxiv.org/html/2605.27366v1)) **[preprint]**, while self-generated skills averaged slightly below no skill in SkillsBench ([SkillsBench](https://arxiv.org/html/2602.12670v3)) **[preprint]**. With 19 drafts unreviewed, the queue is safe and useless. Stop generating while it is over a cap, offer at most three drafts with evidence, and expire the rest. If nobody reviews after a trial, that is the data for removing the surface.

Progressive extraction's 12 writes on 226 calls cannot support keep or delete, since systems with about 90% precision and under 60% recall look the same as discerning ones from outside ([ProMem](https://arxiv.org/pdf/2601.04463)) **[preprint]**. The denominator is also incomplete: failed calls log at `debug!` and accounting fires only on success (`src/memory/progressive.rs:51`, `src/agent/runtime/sdk_provider.rs:244`) **[code]**, so the failure rate that motivates failover is unmeasured. The cheapest failover is still worth adding, but the keep decision needs a recall audit and a session-end batch comparison. One session-granularity system scored 0.902 on LoCoMo against 0.913 for full context with 87% fewer tokens, though no study holds extractor and corpus fixed while varying per-turn against session-end ([Curation and Consolidation](https://arxiv.org/html/2610.39790v1)) **[preprint]**. Mem0 and AWS AgentCore are real counter-examples to dropping it by analogy ([AWS](https://aws.amazon.com/blogs/machine-learning/building-smarter-ai-agents-agentcore-long-term-memory-deep-dive)) **[primary]**.

Consolidation and session analysis use the right chain and tier as far as evidence goes, but `AccountedProvider` records only successes and writes `request.model`, which is the requested model even after failover (`src/agent/runtime/sdk_provider.rs:108`) **[code]**. Procedure enhancement's move to the fast tier should wait. Writer-tier results point both ways: EvoSkill ranged from 10.2% to 20.3% by backbone ([SkillGenBench](https://arxiv.org/html/2605.18693v1)) **[preprint]**, self-written skills did not improve with model strength in SkillsBench **[preprint]**, and Anthropic's Dreams excludes Haiku without saying why ([Dreams](https://platform.claude.com/docs/en/managed-agents/dreams)) **[primary]**. Volume is low, so cost does not force the choice **[inference]**. Failover alone is safe to add, and failure already leaves the procedure unchanged.

The summarizer's separate background pass matches first-party practice ([Anthropic background compaction](https://platform.claude.com/docs/en/build-with-claude/compaction-background)) **[primary]**, but the fast model is its least supported part. Among full-history successes, summary-only continuation failed 5% of the time on one model and 64% on another ([Compact-Bench](https://arxiv.org/html/2610.31710)) **[preprint]**, and LLM summaries retained at most 16% of recurring details against 79.1% for a mechanical index. The result argues for a paired replay and a deterministic block of paths, IDs and open obligations, not for a tier change on faith. The interpreter's case for staying out of the loop is a code comment about small models re-running slow commands (`src/agent/mod.rs:823`) **[code]**, and aidaemon is now hosted-only **[local]**. Failover would add nothing, since a failed sentence falls back to the raw result. Test a template too: the model's one advantage is a caveat such as "matches, not files".

Diagnose's deletion stands on different grounds from the audit's. A September 2026 preprint found a single-call reranker matched or beat the best baseline on all six suites ([Where RCA Fails](https://arxiv.org/pdf/2609.36686)) **[preprint]**, so "deterministic candidates suffice" is unproven, though that test used telemetry RCA with richer per-candidate evidence. The research notes propose a labeled three-arm evaluation; I reject it for now, because `llm_rank_candidates` runs on every diagnose call with events (`src/tools/diagnose.rs:1584`), so zero logged calls means the tool is barely used, and no traffic exists to build a corpus **[code]**. One caveat: its failures return `None` with no record, so zero successes is slightly weaker than zero attempts. The step overwrites deterministic descriptions, applies a 60/40 blend no source supports, and can parse thinking text. An inconclusive result should default to the smaller surface. The next question is whether the tool earns its slot at all.

## One helper is right if the policy is mandatory

Position (a) confirms on policy and fails on its conclusion. Judges and background jobs should differ, and refusals are handled inconsistently across the field: LiteLLM and OpenRouter fall back on them while Claude Code blocks ([LiteLLM](https://docs.litellm.ai/docs/proxy/reliability), [permission modes](https://code.claude.com/docs/en/permission-modes)) **[primary]**. Nothing surveyed forces one policy on all calls, yet Hermes, LiteLLM and the OpenAI Agents SDK each keep one retry mechanism with declared per-call or per-error policy ([Hermes](https://hermes-agent.nousresearch.com/docs/user-guide/features/fallback-providers)) **[primary]**, and Vercel ships a typed decision primitive ([Vercel](https://vercel.com/docs/ai-gateway/models-and-providers/decision-fallbacks)) **[primary]**.

The code shows six shapes, not three: `ask_for_judgment`, the router's own candidate loop, `background_chain`, `RuntimeProvider`, `background_chat` callers recording by hand, and raw `provider.chat` **[code]**. Their differences in recording have no rationale in the code, and the audit's own blind spots come from them. Build a thin core with a required policy and no default failure mode, returning a typed outcome such as valid, refused, truncated, schema-invalid, provider error or skipped. Migrate recording first, compare old and new paths on recorded inputs, and let policies stay exactly as they are. The main risk is that migration quietly changes a tier or deadline **[inference]**.

Position (b) is right on coverage: the four named calls are the only users of `RuntimeProvider` (`conversation_compaction.rs:276`, `progressive.rs:37`, `task_learning.rs:97`, `memory_plugin.rs:271`) **[code]**, and it currently tries only the requested and primary models. It does not reach the interpreter or procedure enhancement. As a one-line change it would make slow failures slower. The research notes' 2,160-second figure overstates a hang, because the chain does not retry an attempt that hit its deadline (`crates/aidaemon-core/src/failover.rs:296`) **[code]**. A hung provider costs 360 seconds per model, so 12 minutes today and 24 with one failover provider of two models; the threefold multiplier applies only to errors that arrive just before the deadline **[inference]**. The 30-second emergency compaction wrapper would still cancel during a first hung attempt, so failover cannot help where it matters most. Add one total deadline, a per-call stall limit and failure records in the same change, and honor quota scope, since a session limit shared across models makes sibling models pointless ([Claude Code costs](https://code.claude.com/docs/en/costs)) **[primary]**. Failover also carries private memory to more vendors, so it needs a per-call data-class rule **[inference]**.

## Conclusion

The audit's weakness was treating logged calls as observed behaviour. A call that fails, is skipped or is answered by a different model looks like nothing or like the wrong thing in the current records, and that single gap explains why the assessor is a mystery and why the failover case is unmeasured. Fix recording before tuning anything else, because it converts most "cannot decide" verdicts here into measurable ones.

The larger shift concerns how to decide. Eight-run A/Bs can only detect large effects, and an 8/8 still allows a true failure rate of about 31% **[inference]**. No public benchmark covers overlapping extraction pipelines or personal-agent procedural learning, so most memory decisions will remain inconclusive at aidaemon's traffic. A default rule is therefore worth adopting explicitly: when a pipeline's ablation is inconclusive, keep the cheaper configuration with the smaller attack surface, and exempt safety judges, which should be judged by replay against labeled cases and never by removal.
